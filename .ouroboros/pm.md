# mini_pjt — EN→KO 카드게임 번역 보조 에이전트

*Created At: 2026-09-16T05:19:14.549532+00:00*

## Goal

과거 공식 번역물에만 암묵적으로 존재하던 용어·문형 규칙을 명시적 자산(용어집·문형·번역메모리)으로 추출하고, 이를 근거로 카드 초벌 번역 생성 + 가드레일 위반 검출 + 사람 승인(HITL)까지 이어지는 파이프라인을 제공해, 번역 일관성이 개인 기량에 좌우되지 않게 한다.

## User Stories

1. **As a** 카드게임 EN→KO 공식 번역가(본인), **I want to** 기존 공식 번역물에서 용어집·문형·번역메모리를 오프라인 배치로 추출하고 싶다, **so that** 기억과 repo grep에 의존하지 않고 지켜야 할 용어·문형을 명시적 자산으로 확보하기 위해.
2. **As a** 동료 번역가, **I want to** 카드 단위 검토 큐에서 초벌 번역과 가드레일 위반 표시를 보고 승인하거나 수정 후 승인하고 싶다, **so that** 매 카드마다 일관성을 스스로 검증하는 부담 없이 빠르게 검토만 하기 위해.
3. **As a** 번역가 팀, **I want to** 구축된 자산과 검토 기능을 MCP 서버로 공유받고 싶다, **so that** 각자 도구를 따로 세팅하지 않고 같은 용어집·문형 기준을 공유하기 위해.
4. **As a** 용어집을 확정하는 번역가, **I want to** 용어 충돌 목록과 신규 용어 후보 목록을 따로 받아 사람이 확정하고 싶다, **so that** 잘못된 역어가 자동 등재되어 전 카드로 전파되는 것을 막기 위해.
5. **As a** 번역가, **I want to** 승인 결과를 원본 repo가 아닌 별도 산출 파일로 받아 직접 커밋하고 싶다, **so that** 팀이 소유하지 않은 공식 공개 저장소에 도구가 직접 쓰는 위험을 피하기 위해.

## Constraints

- 구현 기간 2일, 이후 장기 유지보수 전제
- 원본 코퍼스는 Null Signal Games의 공개 repo(https://github.com/Null-Signal-Games/netrunner-cards-json), 대상 게임은 Android: Netrunner. 팀 소유 저장소가 아닌 공식 공개 저장소다
- 코퍼스는 git repo의 구조화 포맷(json/csv/yaml), 파일 단위 EN↔KO 대응
- 대상 콘텐츠는 카드 룰 텍스트 + 플레이버 텍스트만. 룰북·UI는 범위 제외
- 사전 용어집은 존재하지 않음 — 기존 번역물에서 추출하는 것이 서비스 핵심 기능
- 이미 공개된 카드만 취급하므로 외부 LLM 전송 제약 없음
- 공유 수단은 MCP 서버 노출
- 아키텍처는 2단계 분리: 1단계 자산 구축(오프라인 배치) + 2단계 번역 검토 큐(온라인)
- 용어 후보 생성 단계는 LLM 호출 0회 — EN n-gram × KO 어절 n-gram 공기빈도, Dice/PMI, 최소 등장 5회의 통계로만 후보를 만들고, LLM은 구조화 출력으로 가부 판정만 수행
- Supervisor 패턴과 Plan-Execute는 채택하지 않음. 룰/플레이버 분기는 라우팅으로 처리하며 에이전트 분할이 아님
- 평가 정답셋은 별도 제작하지 않고 기존 번역물 hold-out을 사용. 용어 준수율은 규칙 자동 채점, 문체만 LLM-Judge
- 도구는 원본 git repo에 쓰기를 하지 않는다 — repo 반영과 커밋은 사람이 별도로 수행
- 승인만으로 용어집이 자동 갱신되지 않는다
- 충돌 용어는 사람이 확정하기 전까지 용어집에 포함하지 않는다
- 편집거리 기준선은 새로 수집하지 않고 이미 기록이 남아 있는 과거 무보조 초벌본을 재사용한다

## Success Criteria

1. 하드 게이트 1 (미달 시 납품 거부): hold-out 100장 기준 용어 준수율 ≥ 95%
2. 하드 게이트 2 (미달 시 납품 거부): hold-out 100장 기준 게임 기호·플레이스홀더 보존율 100%
3. 하드 게이트 3 (미달 시 납품 거부): hold-out 100장 기준, 과거 무보조 사람 초벌(기계번역 원본 아님) 대비 편집거리 30% 이상 감소
4. 세 하드 게이트 중 하나라도 미달이면 불합격 — 예시로 용어 준수율 93% / 기호 보존율 100% / 룰 문형 2.6/3은 불합격으로 판정된다
5. 하드 게이트 판정 단위는 hold-out 100장이다
6. 게임 기호·플레이스홀더({T}, {2}{R} 등)를 훼손하거나 번역하면 hard fail 처리한다
7. 용어집에 등재된 용어는 등재된 역어로만 출력하고, 위반 시 차단 후 검토 큐로 보낸다
8. 용어집에 없는 신규 용어를 임의로 창작하지 않으며 HITL 승인을 요구한다
9. 룰 텍스트에서 원문에 없는 효과·조건을 추가하거나 원문의 효과·조건을 누락하지 않는다
10. 카드 텍스트를 지시로 해석하지 않는다(프롬프트 인젝션 방어)
11. 자산 구축 배치가 동일 EN 용어의 상이한 KO 역어 충돌을 발견하면 자동으로 정답을 고르지 않고, '용어 충돌 목록'으로 분리 출력하며 해당 용어를 용어집에서 제외한다 (최신 카드 채택·최빈값 채택 모두 사용하지 않음)
12. 검토 큐에서 승인(또는 수정 후 승인)된 결과는 원본 git repo의 KO 필드에 쓰지 않고 별도 산출 파일(예: approved.jsonl)로만 적재한다
13. 승인된 번역에 용어집에 없던 신규 용어가 포함된 경우 '신규 용어 후보'로만 적재되고, 별도 확정 절차를 거쳐야 용어집에 등재된다 — 승인만으로 다음 카드부터 강제되지 않는다
14. 산출물은 구현을 바로 착수할 수 있는 수준의 PRD

## Assumptions

- 룰 텍스트 문형 일치(LLM-Judge 3점) ≥ 2.5/3과 플레이버 자연스러움 ≥ 2.0/3은 하드 게이트에서 관찰 지표로 강등되었다 — 측정은 하되 미달만으로 납품 거부 사유가 되지 않는다
- 과거 무보조 사람 초벌본의 작업 기록이 실재하며, hold-out 100장의 편집거리 기준선으로 쓰기에 충분한 범위·형태로 남아 있다고 전제한다 (실재 여부·커버리지는 미검증)
- 사용자는 용어 일관성이 이 도구의 존재 이유이고 사람 수정량이 실제로 줄지 않으면 도구를 쓸 이유가 없다고 판단해 하드 게이트를 이 두 축 + 기호 보존으로 한정한 것으로 읽힌다
- 불확실한 항목은 자산에서 아예 제외하고 사람이 항상 마지막 관문을 닫는다는 보수적 원칙이 용어 충돌 처리·승인 결과 적재·신규 용어 등재 전반에 일관되게 적용된다
- 번역가 팀이 이 도구를 실제 카드 번역 워크플로에 채택하는지, 도구 도입 이후 팀 전체의 일관성이 개선되는지는 납품 이후 사용자가 별도로 관찰할 후속 과제이며 납품 계약 조건이 아니다
- hold-out은 과거 카드 일부를 떼어내고 나머지로만 자산을 구축하는 방식으로 구성되며, hold-out 카드는 자산 구축 입력에서 완전히 배제된다
- 선행 인터뷰에서 확답된 전제(코퍼스 형태, 콘텐츠 종류, 사용자, 사용 흐름, 기밀성, 공유 수단, 접근안, 일정)는 재질문 없이 그대로 유효하다
